# tushare 回溯迁移的边界与验收纪律

---
status: accepted
date: 2026-09-13
---

2000 积分档 tushare 到位后（2026-09-13 数据源优先级原则：新增腿默认 tushare 优先），我们决定把**存量的看板只读数据腿**也回溯迁移到 tushare，并立下三条纪律：**①引擎冻结**——引擎决策链所读的表（`daily_prices` ETF 部分、`etf_scale` 份额）不参与任何换源，换源即抽掉 walk-forward 决策门的回测底座，要动须另立项目重做全量验证；**②平移/升级分批**——等口径平移（如 Shibor 换源）与口径/覆盖升级（如两融从沪市单边到沪深两市）不混在同一提交，出了口径差无法归因；**③对账门**——换源前必须在重叠区间对账：精确族（官方同源数）零容差，口径差族（如 daily_basic PE vs 百度）只量化不拦、看报告放行。

## Considered Options

- **连引擎一起迁**：否决。回测结果随口径变，样本外 PASS 失效，验证成本远超收益。
- **一次性大 PR 全换**：否决。逐腿小步（口径对照→重灌→对账→测试→commit）才能把每条口径差归因到腿。
- **无痛腿不迁**：部分否决（用户裁定「全迁」）——本仓库 akshare 端点有腐烂实史（南华死/push2 拦/sina 外盘失真/按股研报死），无痛腿迁移是买端点保险；但有口径工作量的无痛腿仍须过对账门才切。

## Consequences

- 看板数字（估值档、恐贪分位、偏离度极值排名）会因口径换源而变——接受，但每腿产出口径差量化报告备查。
- 旧源 akshare 调用全部留盘做回退链（tushare 失败降级），代码双路径并存、测试面翻倍。
- 一年后看到「ETF 份额还在爬两所官网而 margin 走了 tushare」「南华只有备份通道」——都是本 ADR 的刻意结果，勿"修复"。
